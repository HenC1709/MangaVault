# 5 MVP hasta tener la app ejecutable sin IDE

Meta final: doble clic en `MangaVault.exe` (o acceso directo) sin abrir VS Code / Visual Studio.

Cada MVP termina en algo que se puede **ejecutar y probar**.

---

## MVP 1 – El núcleo arranca y persiste (consola)
**Objetivo:** corregir los errores críticos de `02-errores.md`.
- [x] `Program.cs` con punto de entrada y menú mínimo.
- [x] Arreglar deserialización (`[JsonInclude]`/`[JsonConstructor]`).
- [x] Ruta de datos en `%LOCALAPPDATA%\MangaVault\`; tolerar JSON vacío.
- [x] Generación de Ids; `Update`/`Delete` con excepción si no existe.
- [x] Añadir `MediaType` (Manga/LightNovel).

**Listo cuando:** agregar una obra, cerrar, reabrir y que siga ahí (`dotnet run`).

## MVP 2 – Cuentas + biblioteca personal (consola)
**Objetivo:** implementar la capa Application.
- [x] `UserService` (registro/login con hash PBKDF2), validadores, DTOs, mappers.
- [x] `MangaService`: CRUD + búsqueda por título.
- [x] Progreso de lectura (`MangaEntry`) y favoritos (`FavoriteService`).
- [x] Menús `MainMenu`, `UserMenu`, `MangaMenu` funcionando.
- [x] Mínimo 1 proyecto de tests (xUnit) para servicios.

**Listo cuando:** flujo completo registro → login → agregar obra → marcar progreso/favorito, con tests en verde (`dotnet test`).

## MVP 3 – Base SQLite
**Objetivo:** pasar de JSON a SQL (ver `01-vision-sql.md`).
- [x] Separar en solución: `Core`, `Application`, `Infrastructure`, `Presentation`, `Tests`.
- [x] Crear BD con el DDL al primer arranque.
- [x] `SqliteUserRepository`, `SqliteMangaRepository`, favoritos vía `IsFavorite`.
- [x] Importador opcional desde JSON; seed de géneros.

**Listo cuando:** la app de consola funciona igual pero con `mangavault.db`.

## MVP 4 – Interfaz WPF
**Objetivo:** UI de escritorio (ver `01-vision-wpf.md`).
- [x] Proyecto `MangaVault.Wpf` (MVVM + DI).
- [x] Login/Registro, Biblioteca (lista/grid con filtro Manga/LN), Detalle y Formulario.
- [x] Editar progreso, marcar favorito, búsqueda.
- [x] Mensajes de error amigables y operaciones async.

**Listo cuando:** se puede usar toda la funcionalidad del MVP 2 desde ventanas (ejecutando con `dotnet run --project MangaVault.Wpf`).

## MVP 5 – Ejecutable independiente (sin IDE)
**Objetivo:** distribuir y usar sin herramientas de desarrollo.
- [ ] `dotnet publish -c Release -r win-x64` (single file) → `publish\MangaVault.exe`.
- [ ] Decidir: *framework-dependent* (necesita .NET 10 Desktop Runtime) o *self-contained* (más pesado, no requiere nada).
- [ ] Icono de la app, acceso directo en escritorio (script `.ps1` o instalador MSIX/Inno Setup).
- [ ] Script `build.ps1` que publique con un comando.
- [ ] Backup/exportar desde Ajustes y logs en `%LOCALAPPDATA%\MangaVault\logs`.
- [ ] Prueba en limpio: ejecutar el `.exe` en otra carpeta/PC sin IDE ni SDK.

**Listo cuando:** doble clic en el `.exe` abre la app, guarda datos y los conserva al reiniciar.

---

## Resumen

| MVP | Resultado | Depende de |
|---|---|---|
| 1 | Consola persistente y sin bugs críticos | — |
| 2 | Lógica completa + tests | 1 |
| 3 | SQLite + solución multi-proyecto | 2 |
| 4 | UI WPF | 3 |
| 5 | `.exe` independiente | 4 |

> [!TIP]
> Si quieres un `.exe` antes, tras el MVP 2 ya puedes publicar la versión de consola (`dotnet publish -r win-x64`) y ejecutarla sin IDE; WPF sería un extra posterior.
